# Phase 1 — Foundation (v0.1.0 → v0.1.1)

The initial usable release. Established the file format, the editor, the
MCP server, drift detection, and the publishing pipeline.

## What shipped

| Area | Detail |
|---|---|
| Schema + types | JSON Schemas (Draft 2020-12) for diagram, node-types, and timeline; autogenerated TypeScript types via `json-schema-to-typescript` |
| Hono server | GET/PUT `/api/diagrams`, `/api/timelines`, `/api/node-types`; SSE on `/api/events` |
| Live sync | chokidar watcher with self-write suppression (1.5s); UI refetches on external edits without reload |

## Original implementation items (1-14)

These were the items in the original `implementation-plan.md` covering
the Phase 1 build. All shipped. The text below is the original
description, retained for archaeology — no claim that the
implementations match the wording word-for-word, but the spirit holds.

### 1. Production build path

`pnpm build` produces a self-contained `dist/` such that
`node dist/cli/index.js view` serves the SPA + API on a single port
without Vite. `tsc -p tsconfig.json` compiles the server + CLI; `vite
build` builds the SPA to `dist/view/`. `package.json#files` covers
`dist`, `templates`, `schema`.

### 2. npm publish

Picked the unscoped name `loom-spec` (was available). MIT license.
README at the package root for npm's display. `npm publish` from
`packages/loom-spec/`. Verified with `npx loom-spec init && npx loom-spec view`
from a fresh directory.

### 3. End-to-end test the installed flow

Manual sanity check: `npx loom-spec init`, edit in browser, edit JSON
directly with vim, verify both directions sync, restart cleanly.

### 4. SSE reconnect on the client

EventSource auto-reconnects by default. Hook exposes
`connectionStatus: "connecting" | "open" | "closed"` so the UI can
indicate the state (small dot in top bar).

### 5. Render groups

xyflow v12 group nodes. Compute bounding box of children + padding,
emit a group flow-node at that box's top-left with width/height,
recursive for nested groups. Color from `group.color`, label as
absolutely-positioned chip in the top-left.

### 6. Drill-down navigation

Nodes / groups with `drill_down: "<id>"` show a chevron icon.
Double-click handler changes the active diagram id. Diagram id is in
URL hash (`#diagram:<id>`). Breadcrumb back via `history.pushState`.

### 7. Diagram switcher

`GET /api/diagrams` returns the summary list. Top bar dropdown shows
title + nodeCount/edgeCount. Selecting one updates the URL hash.
"+ New diagram" entry creates an empty diagram via PUT.

### 8. Reposition Add Node menu

Position under the "+ Add" button precisely (via `getBoundingClientRect()`),
no overlap with the inspector.

### 9. Parallel-edge label collision

Two edges between the same node pair: group flow-edges by
`${source}->${target}` at convert time. For groups > 1, assign offset
index (-1, 0, 1, …). Custom `ParallelEdge` draws a bezier with
vertical offset in the middle.

### 10. Code-refs editing

New section in `NodeInspector` below read-only render. Each ref is a
row with three inputs (path, symbol, lines) + delete button.
"+ Add ref" button appends. Validation: at least `path` must be
non-empty.

### 11. Tags editing

Tag input pattern: text input + "Enter to add" + chips above with X
buttons. Tags deduplicated and lowercased on add.

### 12. Ports in the UI

Render named in/out ports as separate handles. In `NodeCard`, instead
of one generic Handle, render one Handle per port from
`typeDef.ports.in` / `typeDef.ports.out`. xyflow's `onConnect` provides
`sourceHandle` / `targetHandle` to build `from` / `to` strings with
`:port` suffixes.

### 13. Inline validation feedback

Schema in browser bundle. `validateDiagram` runs client-side on each
mutation (debounced). Errors map to specific node/edge/field paths
and render as markers in the Inspector and red borders on canvas
nodes.

### 14. Watcher resilience

`chokidar.watch` setup wrapped in try/catch, logs a warning instead of
crashing on startup. Subscribed to `error` events, re-initializes
after a backoff. Disappearing `.loom/` directory emits a synthetic
"loom-root-gone" event so the UI shows an error state.

## Original MCP-server work (Phase 1)

`loom-spec mcp` exposes 10 tools (one per editing primitive). Each
mutation re-reads, applies the patch, validates against the schema,
and writes — invalid edits never corrupt the file.

## Original drift-detection work (Phase 1)

`src/server/drift.ts` walks every `code_refs[]`, checks `path`
existence and `symbol` presence. Skipped for `planned` / `deprecated`
nodes (their code may legitimately not exist). Exposed via CLI
(`loom-spec validate`) with proper exit code for CI / pre-commit.
